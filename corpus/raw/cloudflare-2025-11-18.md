## Summary
On November 18, 2025, Cloudflare suffered a global outage that lasted approximately 3 hours for the main impact, with full recovery after 5 hours 46 minutes. A database permission change, deployed at 11:05 UTC, inadvertently caused the Bot Management configuration file to be generated at roughly double its normal size. When the core proxy service loaded the bloated file, it crashed, returning 5xx HTTP errors to all users. The failure was intermittent at first — the configuration file was rebuilt every 5 minutes from a ClickHouse database cluster, and only nodes that had received the permission update produced the bad file. This fluctuation initially led the team to suspect an attack. Once all nodes were updated, the failure became persistent. Major websites including Spotify, ChatGPT, X, and Canva became unreachable. The incident was resolved by stopping the generation and propagation of the bad configuration file, manually injecting a known-good file, and forcing a global restart of the core proxy. Cloudflare described this as their worst outage since 2019.

## Root Cause
A database access control change, deployed at 11:05 UTC, gave the Bot Management configuration generation query permission to read a much larger dataset than intended. The query ran every 5 minutes against a ClickHouse database cluster to build a configuration file that controls bot detection rules on the core proxy. Because the permission change rolled out gradually across the cluster, some nodes produced a normal-sized file while others produced a file roughly double the intended size, filled with unnecessary rules. When the proxy loaded a bad file, it crashed, causing all traffic to fail with 5xx errors. When a good file was generated by a not-yet-updated node 5 minutes later, the proxy recovered. This alternating pattern continued until all ClickHouse nodes had the permission update, at which point the file was consistently bad and the proxy remained in a failed state. The crash propagated globally because the configuration file was automatically distributed to every proxy instance worldwide.

## Resolution
1. At 13:05 UTC, engineers bypassed Bot Management for Workers KV and Access, reducing some impact.
2. At 13:37 UTC, teams began working to restore a previous known-good version of the Bot Management configuration file.
3. At 14:24 UTC, the automatic generation and propagation of new configuration files was stopped. A test with the old file showed successful recovery.
4. At 14:30 UTC, a known-good configuration file was manually injected into the distribution queue, and a global restart of the core proxy was forced. Core services began functioning normally.
5. By 17:06 UTC, all remaining downstream services that had entered a bad state were restarted, and 5xx error volume returned to normal.

## Prevention
Cloudflare committed to the following follow-up actions:
- Hardening the ingestion of Cloudflare-generated configuration files, applying the same validation used for user-generated input.
- Enabling more global kill switches for features to allow faster isolation.
- Eliminating the ability for core dumps or error reports to overwhelm system resources.
- Reviewing failure modes for error conditions across all core proxy modules to prevent similar cascading failures.
