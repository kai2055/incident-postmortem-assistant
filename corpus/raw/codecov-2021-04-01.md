## Summary

On April 1, 2021, Codecov was alerted to a security event involving its Bash Uploader — a script customers run in CI pipelines to upload coverage reports. A threat actor had extracted an HMAC key for a Google Cloud Storage service account from an intermediate layer in Codecov's public Self-Hosted Docker image, then used that key to modify the Bash Uploader stored in Google Cloud Storage so that the altered version was served directly to end-users. The malicious change extracted git remote origin URLs and environment variables from any environment where the uploader ran, potentially exposing credentials, tokens, and keys present in customers' CI pipelines. The same payload reached users of the Codecov GitHub Action, CircleCI Orb, and Bitrise Step, all of which invoke the Bash Uploader. Detection came from a customer performing SHASUM checking who noticed a discrepancy between the SHA256 published on GitHub and their own calculated hash. Note on duration: Codecov does not state when the attacker first gained access, so `duration_minutes` here measures the detection-to-disclosure window — April 1 to the public Security Update on April 15 (14 days). The true customer-impact window began earlier and is not dated in the source.

## Root Cause

The attacker leveraged two exploits in sequence.

First, an HMAC key for a Google Cloud Storage service account was extracted from an intermediate layer in Codecov's public Self-Hosted Docker image. The image was distributed without squashing or multistage builds, so a layer containing the key remained readable in the published artifact.

Second, that key was used to modify the Bash Uploader stored in Google Cloud Storage, so that the altered script was served directly to end-users.

The malicious code extracted git remote origin URLs and environment variables from the environment in which the uploader executed. Because the Codecov GitHub Action, CircleCI Orb, and Bitrise Step all invoke the Bash Uploader, users of those integrations received the same payload.

A SHASUM validation method for the Bash Uploader had always existed, but Codecov had not fully or properly documented the process required to use it, so the integrity check that would have caught the tampering was available but not in general use.

## Resolution

The key taken by the attacker was revoked, and all production keys were audited and rotated.

All publicly accessible Codecov Docker images were updated to use squashed and/or multistage builds. Previous images were pushed over with new squash builds and all previous versions removed from Docker Hub.

With a third-party forensic team, Codecov conducted a full investigation of its infrastructure, associated logs, and application logs, and confirmed there were no other intrusions or inappropriate access to its systems.

Affected customers were contacted individually by email and in-app notification, and instructed to run `env` in the CI steps that also executed the Bash Uploader, note the variables printed, assess the sensitivity of each, and determine the impact if those credentials had been used by an unauthorized third party.

## Prevention

- **Full key rotation.** All relevant keys rotated, previous keys revoked.
- **Docker image deployment.** All public images now squashed and/or converted to multistage, to prevent a future Docker layer attack.
- **New uploader.** A new Uploader released, shipped as a signed and SHASUM-verifiable binary executable, deprecating the Bash Uploader.
- **Active monitoring.** Any change to the Bash Uploader in Google Cloud Storage now triggers alerts and notifications escalating to the appropriate team members.
- **SHASUM documentation.** External documentation updated to better demonstrate how to perform SHASUM validation of the uploader. Future work is to sign it with a GPG key.
- **Key management.** An in-house tool built for tracking key generation, enforcing rotation policies, and auditing key use — built because existing secret-distribution tools track the secret but not its metadata: when it was generated, where it is used, how it can be revoked.
- **Incident response.** Response processes, policies, and procedures enhanced using the event as a learning exercise.
- **Staffing.** A dedicated security team to be built, starting with product/application security and infrastructure security.
- **Software distribution.** Codecov identifies curl-pipe-to-bash as rife with security issues and a central lesson of the incident, and addressed it by moving to a signed, verifiable binary.
